# Память проекта lac

## Приоритет последней ревизии

Начало разработки 2026-10-02: пользователь явно разрешил установку недостающих инструментов и коммиты по усмотрению в этой работе. Ветка `0.0.1`. Исправлен `code/zero.l` на `Point(&P)`. Установлены Clang/libclang 16.0.5 и LibTomMath 1.2.0 в MSYS2 UCRT64; GCC/CMake/Git уже были. План — `docs/implementation-plan.md`. Добавлен первый рабочий C-компилятор в src, runtime-header, PowerShell build/test и CMake; zero.l компилируется в exe. Это bootstrap-срез, не полный 0.0.1: int64 вместо ещё не подключённого bignum, не готовы массивы/условия/тип результата по @/анонимные лямбды/FFI. README описывает ограничения. По утверждённому примеру `S` временно разрешён как string-значение с owned буфером и lowercase handle; s/S требует дальнейшей формализации.

Последняя проверка zero.l: принято `prl` = println вместо `prln`; алиас `prln` не подтверждён. В файле исправлены `p.x/p.y` и имена владельцев, но остаётся `Point(&p)` внутри main, где объявлен только P; требуется `Point(&P)`. Файл не меняли. Новый пример `A[1].i` означает предложенный вызов преобразования через точку вместо `i(A[1])`; учесть при формализации. Отношение `s/S` остаётся открытым. Коммит только по новой команде.

Уточнение zero.l 2026-10-02: пользователь подтвердил uppercase-владельцев, доступ к именованному параметру по имени и явный `Point(&P)` для копирования. `pr` — print без newline, `prln` — println; `prl` не принят как alias. `main` без возврата — успех, exit code 0. `i(string)` временно atoi-подобный разбор без исключений; строгий вариант возможен позже. При чтении файла ещё обнаружены `.x/.y` у именованного параметра, `Point(p)` и `prl`; исходник не меняли, сообщили пользователю о расхождении с подтверждёнными правилами. `s/S` остаётся открытым.

2026-10-02: пользователь добавил другую эталонную программу `code/zero.l`; исходник не изменять автоматически. Разбор — [zero-program.md](docs/zero-program.md). Пример не требует отложенных коллекций/sequence, содержит создание и копию Point, `#`/`~`, функцию-значение, `&`, интерполяцию. Не считать автоматически пересмотренными прежние правила: lowercase `p=Point` запрещён; точка у названного параметра не согласована; автоматическое заимствование копирующим конструктором и встроенные `pr/prl`, `s/S` ещё требуют уточнения. Предлагается zero.l как минимальный сквозной эталон после уточнений, без коммита.

Последние решения 2026-10-02: компилятор на C. `i/u` расширяемые, `i32/u32/i64/u64` фиксированные. Для обсуждённого underflow unsigned debug — паника, release — заворот; если паника задерживает реализацию, допустим временный заворот и в debug с переносом паники. Модуль заворота расширяемого `u` открыт. Безымянный параметр доступен через `.`, названный — по объявленному имени; имя вызывающего не наследуется. Пользователь добавил `code/first.l` как первую программу; файл не менять автоматически. Новые конструкции и расхождения — [first-program.md](docs/first-program.md): пример использует отложенные коллекции/filter/map, кириллицу при ASCII, `==`, `$`, implicit immutable borrow, `.{} ` и вызовы функций через точку. Уточнения запросили; пока не считать молча принятыми. Коммит не делать.

Уточнения 2026-10-02 имеют приоритет над сводкой ниже: главный критерий выбора реализации — скорость компиляции; C и другие варианты сравниваем, язык не выбран. Приняты явные заимствования `read(p&Point){}` / `read(&P)`, `edit(p*Point){}` / `edit(*P)` и передача владения `take(Point){}` / `take(P)`. Безымянный аргумент доступен как `.`; наследование имени вызывающего ещё требует решения. Для целочисленного переполнения выбран bignum с расширением памяти; применение к фиксированным типам, отрицательные `u`, деление на ноль и floating point открыты. `count:ii=3` подтверждён. Входной `S[]` исключает имя программы и живёт всю программу. Подробности и предложения — [version-0.0.1.md](docs/version-0.0.1.md). Коммит только по команде.

Для 0.0.1 первичны ответы в [version-0.0.1.md](docs/version-0.0.1.md): Windows; ядро из чисел/строк/функций/условий/структур/массивов/лямбд; коллекции и sequence — следующая версия; лямбды без захватов; `.cp`/`.dpcp` отложены. CLI: `lac file.l @ app.exe`, `lac file.l`, `lac 'код' @ app.exe`, `lac 'код'`; default `a.exe`. `main` или `m`, обе вместе — ошибка, иначе первая функция; вход получает статический immutable `S[]` параметров программы (точная сигнатура открыта). Тип результата выводится по `@`, разные возвращаемые типы — ошибка. Immutable-маркер `i` перед типом (точные формы открыты). Интерполяция `{expr}` принята, буквальные скобки `\{`/`\}`. `&`/`|` короткозамкнуты. Индексы с нуля, `a..b` исключает `b`, выход за границы — диагностика и завершение. C-сигнатуры автоматически из `.h`, поднабор чисел/строк; Clang допустим. Язык компилятора, заимствования, overflow и эталонные программы ещё выбираются. Коммит не делать без команды.

Актуальные изменения пользователя описаны в [revision-02.md](docs/revision-02.md) и имеют приоритет над историческими пунктами ниже и исследовательским отчётом:

- Строки только закрытые двойными кавычками; прежние сокращённые строки отменены. Обычная строка — неизменяемая ASCII-структура `{data, size}`: данные без завершающего NUL, размер хранится отдельно. Представление подтверждено пользователем; данные и поля строки неизменяемы. UTF-16 для обычной строки отменён; ширина `c` ещё требует пересмотра. `u8/u16/u32`-литералы — будущее.
- У всех коллекций нужны неизменяемые аналоги; явно названы `iList`, `iSet`, `iArr`. Добавление, удаление и замена элементов запрещены; `fe` с действием допустим, режим записи результата — нет. Глубокая неизменяемость вложенных объектов, остальные имена и преобразования ещё не определены.
- `{expr}` без `$` для интерполяции принято для 0.0.1; буквальные фигурные скобки экранируются `\{` и `\}`. Точная грамматика выражения внутри ещё формализуется.
- Память без GC, минимальный runtime, близость к C. Принят единственный владелец, как в Rust, без RC. Присваивание владельца передаёт владение и запрещает дальнейшее использование источника; примитивы копируются по значению. Компилятор вставляет cleanup, явные `delete`/вызовы деструктора не нужны. Заимствования не должны переживать владельца; синтаксис и правила проверки, захваты, `.cp`/`.dpcp` ещё требуют определения. Регионы и ARC — рассмотренные альтернативы, не принятое ядро; [memory-without-gc.md](docs/memory-without-gc.md). Java-подобная сборка недостижимых циклов больше не требуется.
- Прежнее разрешение перекрёстных ссылок без анализа циклов нужно согласовать с новым уникальным владением: невладеющие связи и владение различаются. Непроверяемые адреса остаются ответственностью программиста; безопасные заимствования требуют ограничений времени жизни. Профайлер предложен, но не выбран инструмент; не обещать статическую безопасность непроверяемых адресов.
- `[..]` заменён на `array.fe{...}`. Callback с явным `@` нового значения предназначен для мутации элемента; callback без `@` — действие. Актуальная краткая форма `fe{@(+1)}`, прежняя `fe{+1}` не возвращает результата. `fe{println(.)}` печатает элементы без случайной записи результата вызова. Семантика именованного изменяемого аргумента ещё требует определения.
- `array.(x:ArrayElementType){@(x+1)}` — отдельная ленивая трансформация без изменения источника. `.collect` собирает в семейство исходного контейнера, `.List`/`.Set`/`.arr` задают целевой вид; Map и изменяющийся тип элемента требуют детализации.
- Возврат в функциях и лямбдах через `@val`; прежний `>val` отменён. Лямбда без `@` ничего не возвращает; неявный возврат последнего выражения отменён. Примеры: `sum(a:i,b:i):i{@(a+b)}`, `():i{@(a+b)}`. Проверка всех путей возврата и возврат без значения ещё требуют формализации.
- `>`/`<` между разными типами — ошибка компиляции. `#` — сравнение адресов ссылок; разные структуры сравнивать нельзя. `#` двух float/double запрещён. `~` — сравнение объектов по значению; floating/value equality ещё нужно описать.
- Логические `& | ! ^`; побитовые функции `ba bo bx sh/shr shl ush inv`. Короткое замыкание и точные типы сдвигов не заданы. Прежние `and/or/xor/&&/||` не считать выбранными алиасами.
- Внешние nullable-коллекции обязательно проходят `.fnn` или `.n`, внешняя nullable-переменная — `val?A:B` с обработкой null. Сигнатуры и отличия от bool-ветвления открыты.
- Первый драфт по-прежнему Linux/Windows, генерация C, импорт конкретных `.h`, результат в заданном файле либо `a.exe`; temp-run и кэш низкого приоритета. Коммит только по указанию пользователя.

## Утверждённые пользователем направления

- lac — очень лаконичный язык работы с файлами и системными утилитами, расширение или переработка Bash с возможностями языка высокого уровня вроде Kotlin.
- Строгая типизация. Первый драфт для Linux и Windows генерирует C только для кода lac; внешние команды и pipe не входят. Разрешены функции C через импорт заголовков `import *.h`, включая стандартную библиотеку; позже появятся алиасы lac. Последнее решение: сейчас компилируем в файл с заданным названием, либо в `a.exe` (пока и для Linux). Синтаксис флага не выбран. Прежние компиляция во временную папку и запуск без `>>` перенесены в низкий приоритет; кэш бинарников также не обязателен. C toolchain пока не выбран.
- Типы: знаковые `i32/i64` или `i`, беззнаковые `u32/u64` или `u`, `f/d`, `c`, `b`. Типы указателей — с большой буквы.
- Примитивные типы по определению хранятся по значению, в том числе в коллекциях, без обязательного boxing или отдельного подсчёта ссылок. Явные указатели на примитивы — отдельные типы.
- Имена переменных без цифр, camelCase или snake_case.
- Создание всегда включает инициализацию; присваиваемого `null` нет.
- `{}` — scope, `[]` — массивы, `? A : B` — возвращающее значение ветвление с bool-условием. Дополнительно нужны `if/else` как в C; логические `and`, `or`, `xor`, `||`, `&&`, `!`.
- Функции как значения, анонимные лямбды, анонимные структуры, функции в структурах; методы — сахар, по умолчанию функции статические.
- Функция: `sum(a:i,b:i):i{a+b}`; лямбда: `():i{a+b}`. `:i` возвращает значение; последнее выражение в примере — результат. `i(a+b)` — значение на стеке, `I(a+b)` — объект в куче. Захват имён в лямбде и ранний возврат ещё нужно определить.
- Доступ через точку. Объект предложен как массив объектов с индексным доступом; смысл ещё нужно уточнить.
- Диапазоны `1..9`, `a..z`; pipe `|` для функционального стиля и работы с утилитами.
- `(a1..9){arr[a]+1}` возвращает результаты лямбды для индексов 1–9. `arr(1..9).+1` применяет `sum(value, 1)` к тем же элементам и возвращает результаты.
- `s` — строковый тип, строки иммутабельны. `c` использует UTF-16, размер строки соответствует числу элементов массива символов; точное подтверждение кодовых единиц против Unicode-символов ещё нужно. Мутабельный массив символов преобразуется в строку через `S()` или `.toS`. Интерполяция `$val` и `$val.lenght`, включая значения и методы. Нужны регулярные выражения.
- Строка открывается двойной кавычкой; без закрывающей её завершают неэкранированные `)`, `}`, `]`, `,`. Символы можно включать в текст явным закрытием или экранированием (последнее уточняет прежний запрет). Экранируются также `$`, кавычка и обратная косая черта. Пустая строка — `""`; `f("a","b")` равно `f("a,"b)`. Алгоритм однозначного разбора ещё не выбран.
- `db_item{...}` описывает структуру. Поле `type="warn` имеет значение по умолчанию и выведенный строковый тип. `db_item(...)` вызывает конструктор; пользователь также допускает совмещение конструктора с определением структуры.
- Точка входа — первая функция, включая анонимную `(s){...}` с типом строки без имени параметра. `(s)` получает весь вывод программы лениво. Можно задать вход явно как `main()` или `m()`. Компиляция из файла или командной строки.
- Range — фиксированные границы; Sequence — ленивое вычисление. Есть только оператор `..`; `0...size` — это `0..` и `.size`. `{0..5}` — heap-лямбда, задающая sequence; `seq={0..5}` создаёт именованный счётчик, `.next` сохраняет состояние. Все лямбды в куче. Границы и завершение не определены.
- `.` — краткое `it`, элемент коллекции/потока либо анонимный аргумент в scope функции. `[..]` — forEach по всему массиву. `.{func(.)}` обходит sequence/массив или применяется к анонимной переменной.
- `.collect` равнозначно `.collect()`, потребляет sequence/stream до завершения, собирает результат и закрывает источник; может приводить к коллекции. Целевой контейнер и результат по умолчанию ещё не выбраны. Методы без аргументов можно вызывать без скобок.
- Конструкция `array.{body}` обходит каждое значение массива; после `.collect` блок выполняется поэлементно.
- `>> script.exe` обсуждался для сохранения скомпилированного сценария с вызовом `grep`; актуальное имя по умолчанию — только `a.exe`, прежнее `a.out` отменено последним уточнением. Утилиты вызываются из системы, не упаковываются; без установленного grep сценарий не работает. Внешние команды отложены. Возможные отдельные объектные файлы этапов pipe — предложение, не решение.
- Запуск `lac` без аргументов открывает редактор с подсветкой определений переменных, функций, структур и других конструкций.
- Первоначально память планировалась через RC. Последнее желание — Java-подобная достижимость: нет пути из активных корней через граф объектов — объект подлежит удалению. RC сам по себе не собирает недостижимые циклы; алгоритм GC/обнаружения циклов ещё не выбран. Ссылок на стековые объекты нет; автоматический перенос в кучу при попытке создать ссылку рассматривается, но не принят. Borrow checker пока не требуется.
- Последнее уточнение размещения: `db_item(...)` создаёт объект на стеке, `Db_item(...)` — в куче; описание остаётся `db_item{...}`. Это меняет ранее предложенную связь большой буквы со стеком. Пользователь предложил в эталонном примере использовать `.Db_item(...)` из-за объёма данных. Оба варианта синтаксически допустимы; неподходящий выбор размещения — ошибка программиста.
- Последнее правило структур: `p=point(...)` — прямое значение на стеке; `P=Point(...)` — указатель P на стеке, объект в куче; `p=Point(...)` — ошибка компиляции. Прежний `P=point(...)` не считать согласованным примером. `seq={}` разрешено как указатель на функцию с маленьким именем. Объявления примитивов `a:d=3`, `a=5.55`, `A=3` сохраняются; формализация указателей-примитивов ещё нужна.
- `i32/u32/f` — 32 бита, `i/u/d` — 64 бита. Типа `y` нет: это был русский предлог «у». Импорт любого конкретного `.h`, не wildcard. Автоматические числовые преобразования как в C, явные через конструктор типа. `d:b=1` — допустимая инициализация, но условие требует bool.
- Массивы хранят сами значения/объекты непосредственно; коллекции `Array`, `Map` и другие хранят ссылки на объекты, а примитивы — по значению. `Array` в lac — коллекция, отличная от обычного массива. Это собственная модель lac, не точная копия Kotlin/JVM.
- Присваивание ссылок копирует адрес в куче. `Pnt=Point(p)` — копия объекта в куче; прежний `pnt=Point(p)` запрещён последним правилом. `.cp` — копия, `.dpcp` — глубокая копия; типы/размещение результатов методов и копии графов ещё нужно определить.
- `Map` и коллекции не содержат null. `getIfPresentOr` принимает лямбду, вызываемую при отсутствии значения; полная сигнатура не задана. `(try)? :` как аналог try/catch — предложение, не решение.
- Необработанную ошибку пользователь предложил завершать как `Segmentation fault`; реализация исключений и кроссплатформенное поведение не определены. Для sequence нужен безопасный метод и предложена форма `=seq.next?{/*what to do if exp*/}`. Значение обработчика и различие с тернарным `? :` ещё не выбраны.
- Требуется определить размещение буфера `.collect`, поведение при сборе sequence указателей, целевой контейнер и время жизни значений. Не утверждать, что стековые временные объекты обязательно накапливаются: перенос значения и переиспользование слота могут менять поведение.

## Не выдавать предложения за решения

Не утверждены: язык реализации компилятора, точные правила проверки типов, совместимость с Bash, ленивость преобразований массивов, нулевая индексация, точная единица длины UTF-16, `${...}`, `length`, немедленное освобождение, алгоритм GC, слабые ссылки, `Option<T>`, однопоточная модель и изменяемость объектов. C-бэкенд, UTF-16, иммутабельные строки и размеры `i/u/f/d` уже выбраны.

Открытые вопросы: разбор строк, EOF, sequence внутри обхода и исчерпание, вложенная точка, область определения структур, точка входа, FFI-сигнатуры и C-указатели, GC и копии графов, исключения, интерфейс редактора. Упаковка утилит не требуется. `..`/`...`, `[..]`, отсутствие типа `y`, смысл импорта и базовая сигнатура функции уже уточнены.

Предложение для парсера: завершающая скобка или запятая не входит в значение строки и остаётся частью окружающей конструкции. Это детализация ассистента, отдельно не утверждённая пользователем.

Подробности: [спецификация](docs/language.md), [план](docs/roadmap.md).

Нерешённые детали и предлагаемый порядок не считать решениями. Просить примеры с входом, результатом и его типом, побочными действиями и ошибками.

## Порядок дальнейшей работы

Продолжать обсуждение конкретными короткими программами и уточнять семантику до реализации. Сохранять краткость синтаксиса как основную цель. При изменении решений обновлять эту память и соответствующий раздел спецификации.

Коммиты делать только по явному указанию пользователя. Документацию и память можно обновлять без коммита.
