# Память проекта lac

Обновлено: 2026-10-01. Это локальная память проекта, сохраняемая в Git.

## Утверждённые пользователем направления

- lac — очень лаконичный язык работы с файлами и системными утилитами, расширение или переработка Bash с возможностями языка высокого уровня вроде Kotlin.
- Строгая типизация. Без `>>` — однократное выполнение; `>> имя` — компиляция всего сценария в исполняемый файл. Бэкенд и механизм исполнения ещё открыты.
- Типы: знаковые `i32/i64` или `i`, беззнаковые `u32/u64` или `u`, `f/d`, `c`, `b`. Типы указателей — с большой буквы.
- Имена переменных без цифр, camelCase или snake_case.
- Создание всегда включает инициализацию; присваиваемого `null` нет.
- `{}` — scope, `[]` — массивы, `? A : B` — возвращающее значение ветвление.
- Функции как значения, анонимные лямбды, анонимные структуры, функции в структурах; методы — сахар, по умолчанию функции статические.
- Доступ через точку. Объект предложен как массив объектов с индексным доступом; смысл ещё нужно уточнить.
- Диапазоны `1..9`, `a..z`; pipe `|` для функционального стиля и работы с утилитами.
- `(a1..9){arr[a]+1}` возвращает результаты лямбды для индексов 1–9. `arr(1..9).+1` применяет `sum(value, 1)` к тем же элементам и возвращает результаты.
- `s` — строковый тип. Строки как массивы char; интерполяция `$val` и `$val.lenght`, включая внутренние значения и методы. Нужны регулярные выражения.
- Строка обязательно открывается двойной кавычкой; закрывающая необязательна. Пользователь уточнил: любая закрывающая скобка `)`, `}` или `]` завершает строку. Не исправлять автоматически незакрытые строки в пользовательских примерах.
- `db_item{...}` описывает структуру. Поле `type="warn` имеет значение по умолчанию и выведенный строковый тип. `db_item(...)` вызывает конструктор; пользователь также допускает совмещение конструктора с определением структуры.
- Точка входа — первая функция, включая анонимную `(s){...}` с типом строки без имени параметра. Можно задать вход явно как `main()` или `m()`.
- Range — ленивая sequence; `.next` выдаёт следующее значение. `[0...size]` в примере — от 0 до размера текущего массива `.`, включение верхней границы не уточнено.
- `.collect` равнозначно `.collect()`, собирает sequence в массив и закрывает её. Методы без аргументов можно вызывать без скобок.
- Конструкция `array.{body}` обходит каждое значение массива; после `.collect` блок выполняется поэлементно.
- `>> script.exe` сохраняет скомпилированный сценарий вместе с этапом `grep`; без имени результат — `a.exe` или `a.out`. Механизм включения утилит ещё нужно определить.
- Запуск `lac` без аргументов открывает редактор с подсветкой определений переменных, функций, структур и других конструкций.
- Последнее решение по памяти: для начала простые умные указатели с подсчётом владений; после исчезновения всех ссылок объект помечается на удаление. Ориентир Rust обсуждался раньше, но borrow checker пока не требуется.
- Пользователь предложил стековое размещение при создании через указатель с большой буквы. Не считать вопрос решённым: он требует согласования с временем жизни и подсчётом ссылок.

## Не выдавать предложения за решения

Не утверждены: генерация C, LLVM, язык реализации, статическая проверка, совместимость с Bash, ленивость преобразований массивов (ленивость range уже задана), нулевая индексация, конкретные размеры сокращённых типов, Unicode-модель, `${...}`, `length`, немедленное освобождение, слабые ссылки, `Option<T>`, однопоточная модель и правила изменяемости.

Новые открытые вопросы: экранирование скобок и их действие в явно закрытых строках, разделение строковых аргументов запятой, EOF, различие `..`/`...`, состояние range внутри обхода, значение `[..]`, контекст точки, вывод имён полей при конструкторе-определении, выбор точки входа, упаковка внешних утилит и интерфейс редактора. Эталонная однострочная программа сохранена в спецификации.

Предложение для парсера: скобка, закрывающая строку, не входит в её значение и закрывает окружающую конструкцию. Это детализация ассистента, отдельно не утверждённая пользователем.

Подробности: [спецификация](docs/language.md), [план](docs/roadmap.md).
