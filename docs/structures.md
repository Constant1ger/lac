# Объявленные структуры

Реализовано 2026-10-02 по эталону `code/test.l`:

```lac
(){
  A(n:i,tx:S)
  B=A(2,"tt")
  B.tx.pr
}
```

`A(n:i,tx:S)` описывает поля и не создаёт объект. Конструктор `A(2,"tt")` размещает объект в куче; имя владельца `B` начинается с большой буквы. Поля доступны через точку. Программа печатает `tt` без перевода строки и завершается с кодом 0.

Описание полей также записывается в фигурных скобках: `a{n:i,tx:S}` эквивалентно `a(n:i,tx:S)`. Обе формы допустимы в последовательной программе верхнего уровня и внутри функции.

## Стек и куча

`a` и `A` — один тип структуры; регистр первой буквы конструктора выбирает размещение. Определять тип можно любой формой: `a(n:i,tx:S)` или `A(n:i,tx:S)`, обе вместе — повторное объявление. Остальная часть имени учитывает регистр.

```lac
{
  a(n:i,tx:S)
  f=a(2,"tt")
  D=A(2,"tt")
  prl(f#D) // false: разные адреса
  prl(f~D) // true: равны значения всех полей
}
```

Нижний регистр конструктора создаёт заголовок объекта на стеке; верхний — в куче. Имя стекового значения должно начинаться с маленькой буквы, владельца в куче — с большой. Строковые/bignum-буферы полей при необходимости используют кучу при обоих видах размещения. Cleanup стекового объекта освобождает его поля, но не вызывает free для заголовка.

`q=f` копирует стековое значение независимо и сохраняет доступ к f. `a(&D)` копирует объект из кучи на стек; `A(&f)` — со стека в кучу. Присваивание владельца в куче по-прежнему передаёт владение. Стековые параметры и результаты обозначаются lowercase-типом: `id(x:a):a{@x}`; для результата также работает вывод типа. Поля копируются независимо при вызове и возврате, адрес локального объекта из функции не возвращается. Результат с явно заданным heap-типом A требует heap-конструктора.

Сравнение `#` работает по адресу для стековых и heap-объектов одного типа; `~` сравнивает все поля. Сравнения разных типов структур — ошибка. Временное заимствование `read(&f)` допустимо во время вызова; сохранять заимствованный адрес в переменной или возвращать его как владельца нельзя.

Поддержаны поля `i`, `d`, `f`, `b`, `s/S`. Типы аргументов конструктора должны точно совпадать с объявленными. Можно передавать значения по позиции либо именами в порядке объявления: `A(n=2,tx="tt")`. Повторные поля/объявления, неверные типы, количество или порядок аргументов диагностируются.

Большие целые и строки копируются в собственные буферы полей. Поэтому переданная строковая переменная сохраняет своё значение и остаётся доступной. `C=A(&B)` создаёт независимую копию всех поддержанных полей. Доступ к строковому/целочисленному полю возвращает независимое значение; его можно возвращать из функции. Compiler cleanup освобождает буферы полей и объект без GC. `#` сравнивает адреса, `~` — значения всех полей, включая содержимое строк.

## Текущие ограничения

Объявления разбираются внутри функции и в последовательной программе верхнего уровня. В bootstrap таблица типов общая для файла: имя структуры должно быть уникальным даже при объявлениях в разных функциях. Полноценные локальные пространства типов и отдельные глобальные объявления в программе с явно заданными функциями — последующее расширение. Имена полей остаются локальными для типа.

Вложенные владельцы, массивы и функции в полях и default values пока не реализованы. Прежние конструкторы с одновременным определением `Point(x=1,y=2)`/`point(x=1,y=2)` сохраняются; их поля пока выводятся как `i`. Для строковых и иных полей нужно явное объявление, как в примере выше. Владение heap-объектом в параметре функции пока не поддерживается; используются временные заимствования либо стековое значение.

`scripts/test-structures.ps1` включён в общий `scripts/test.ps1`: проверяет эталон, типы полей, оба вида конструктора, копирование/возврат строк, сравнения, интерполяцию, баланс выделений памяти и 11 некорректных программ.
