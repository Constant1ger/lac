# Объявленные структуры

Реализовано 2026-10-02 по эталону `code/test.l`:

```lac
(){
  A(n:i,tx:S)
  B=A(2,"tt")
  B.tx.pr
}
```

`A(n:i,tx:S)` описывает поля и не создаёт объект. Конструктор `A(2,"tt")` размещает объект в куче; имя владельца `B` начинается с большой буквы. Поля доступны через точку. Программа печатает `tt` без перевода строки и завершается с кодом 0.

Поддержаны поля `i`, `d`, `f`, `b`, `s/S`. Типы аргументов конструктора должны точно совпадать с объявленными. Можно передавать значения по позиции либо именами в порядке объявления: `A(n=2,tx="tt")`. Повторные поля/объявления, неверные типы, количество или порядок аргументов диагностируются.

Большие целые и строки копируются в собственные буферы полей. Поэтому переданная строковая переменная сохраняет своё значение и остаётся доступной. `C=A(&B)` создаёт независимую копию всех поддержанных полей. Доступ к строковому/целочисленному полю возвращает независимое значение; его можно возвращать из функции. Compiler cleanup освобождает буферы полей и объект без GC. `#` сравнивает адреса, `~` — значения всех полей, включая содержимое строк.

## Текущие ограничения

Объявления разбираются внутри функции. В bootstrap таблица типов общая для файла: имя структуры должно быть уникальным даже при объявлениях в разных функциях. Полноценные локальные пространства типов и объявления на верхнем уровне — последующее расширение. Имена полей остаются локальными для типа.

Вложенные владельцы, массивы и функции в полях, default values и стековые конструкторы пока не реализованы. Прежние конструкторы с одновременным определением `Point(x=1,y=2)` сохраняются; их поля пока выводятся как `i`. Для строковых и иных полей нужно явное объявление, как в примере выше.

`scripts/test-structures.ps1` включён в общий `scripts/test.ps1`: проверяет эталон, типы полей, оба вида конструктора, копирование/возврат строк, сравнения, интерполяцию, баланс выделений памяти и 11 некорректных программ.
