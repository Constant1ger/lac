# Основа первого драфта lac

Актуальный объём реализации и новые ответы — [lac 0.0.1](version-0.0.1.md). Этот документ сохраняет историю более широкого драфта.

Последняя [ревизия 2](revision-02.md) заменяет ниже прежние правила строк, обхода, операторов и направления памяти. Этот файл сохраняет предыдущую основу; при конфликте руководствоваться ревизией 2. Сборка в заданный файл либо `a.exe` остаётся действующей.

Ответы пользователя, 2026-10-01. Здесь зафиксированы выбранные направления; компилятор ещё не реализован. Нерешённые детали не заменяются предположениями.

## Цель

- Linux и Windows.
- Компиляция собственного кода lac в C.
- Внешние программы вроде grep не входят в первый драфт.
- Pipe отложен. В будущих сценариях grep вызывается из системы и должен быть установлен.
- Явный импорт любого конкретного заголовочного файла `.h`; `import *.h` было обозначением этой возможности, а не wildcard. После импорта доступны функции C, включая стандартную библиотеку.
- Позднее для этих функций планируются алиасы lac без явного импорта.
- Исходник поступает из файла или командной строки.
- Актуальное решение: компиляция создаёт файл с заданным названием, а без названия — `a.exe`. Это имя по умолчанию пока одинаково для Linux и Windows; синтаксис флага не выбран.
- Сборка во временную папку и однократный запуск перенесены в низкий приоритет. Кэш бинарников по хэшу также не входит в обязательную часть первого драфта.
- Входная `(s)` получает весь вывод программы лениво; реализация ленивого строкового входа ещё не выбрана.

## Объявления и размещение

```plaintext
a:d=3 b:u=3 c:s="text", d:b=1
a=5.55 b=3f c="test"
A=3 B=5.5 C=true
p=point(x=4.4,y=5.1)
P=point(4.4,5.1)
Point(1f,6.2)
```

Явный тип — `имя:тип=значение`; без типа используется вывод. Для структур актуальны формы `p=point(...)` (значение на стеке) и `P=Point(...)` (указатель на стеке на объект в куче). `p=Point(...)` — ошибка компиляции. Сам указатель и объект имеют разное размещение. `seq={}` допускается как указатель на функцию с маленьким именем. Heap-примитив и обычный примитив также различаются: объект и содержащий адрес handle — разные сущности.

Первый вызов `point` с именованными полями одновременно определяет структуру и создаёт значение. Следующие позиционные вызовы используют это описание. `Point(...)` создаёт анонимное значение в куче. Heap-пример `P=point(...)` выше сохранён как исторический; теперь согласован `P=Point(...)`. Правила области видимости определения и повторных определений ещё не выбраны.

Присваивание ссылок копирует адрес объекта в куче. `Pnt=Point(p)` создаёт явную копию в куче; исходный пример `pnt=Point(p)` теперь запрещён. `.cp` копирует объект, `.dpcp` делает глубокую копию. Размещение результатов методов и копирование графа требуют детализации.

## Функции и результаты

```plaintext
sum(a:i,b:i):i{a+b}
():i{a+b}
i(a+b)
I(a+b)
```

`:i` — явный возвращаемый тип значения, последнее выражение в примере является результатом. `i(...)` создаёт значение на стеке, `I(...)` — объект в куче. Пустые скобки лямбды не объявляют `a` и `b`; их захват из окружения нужно формализовать. Возврат значения не означает разрешение возвращать адрес локального стекового объекта.

Ссылок на стековые объекты нет. Возможное автоматическое перемещение в кучу при получении ссылки ещё обсуждается. Желаемая память — удаление недостижимых объектов, как в Java; RC был предложен ранее, но алгоритм освобождения циклов ещё нужно выбрать.

## Строки

- Явно закрытые строки могут содержать скобки и запятые.
- Без закрывающей кавычки строку завершают неэкранированные `)`, `}`, `]`, `,`.
- Эти символы можно включать в сокращённую строку экранированием.
- Экранируются также `$`, кавычка и сама обратная косая черта.
- Пустая строка: `""`.
- `c` использует UTF-16; строки иммутабельны, размер соответствует числу элементов массива символов.
- Массив символов может быть мутабельным и преобразуется в строку через `S()` или `.toS`; сигнатура и владение буфером пока не определены.
- `f("a","b")` равно `f("a,"b)`.
- Запятая внутри одного аргумента допускается при явном закрытии или экранировании.

Однозначное распознавание нескольких соседних литералов, таблица escape-последовательностей и завершение на EOF требуют формализации. Ранее обсуждённый запрет скобок в незакрытой строке уточнён: экранированные скобки разрешены.

## Числа и логика

- `i32`, `u32`, `f`: 32 бита.
- `i`, `u`, `d`: 64 бита.
- Типа `y` нет: это был русский предлог «у».
- Автоматические числовые преобразования как в C.
- Явное преобразование: конструктор типа `d(value)`.
- Условие тернарного выражения принимает только `b`; также нужны `if/else` как в C.
- Логические операции: `and`, `or`, `xor`, `||`, `&&`, `!`.
- Пример `d:b=1` задаёт числовой инициализатор логической переменной; конкретное правило преобразования надо описать отдельно от требования bool-условия.

## Обход и sequence

- `.` эквивалентна `it`: текущий элемент коллекции/потока или анонимный аргумент функции.
- `.{func(.)}` применяет лямбду к элементам sequence/массива либо к анонимной переменной.
- `[..]` — forEach по всему массиву.
- Единственный оператор диапазона — `..`.
- `0...size` разбирается как `0..` и `.size`, а не как новый оператор.
- `Range` хранит фиксированные границы; `Sequence` выполняет вычисления лениво.
- `{0..5}` задаёт sequence как анонимную heap-лямбду.
- `seq={0..5}` создаёт именованный счётчик; `seq.next` выдаёт очередное значение с сохранением состояния.
- Все лямбды размещаются в куче; это не требует размещения каждого содержащего их handle на куче.
- `.collect` потребляет источник до завершения и собирает результат, может приводить его к коллекции; выбор контейнера и тип по умолчанию ещё открыты. Вызов без скобок допустим для метода без аргументов.

## Коллекции и отсутствие значения

`Map` и другие коллекции не допускают `null`. Пока используется `getIfPresentOr` с лямбдой, вызываемой при отсутствии значения. Полная сигнатура ещё не задана. `(try)? :` как аналог try/catch — возможное будущее решение, не утверждённый синтаксис.

Для необработанных ошибок пользователь предложил аварийное завершение с `Segmentation fault`; механизм исключений и кроссплатформенное завершение ещё не определены. Для sequence требуется безопасный метод по аналогии с коллекциями и форма `=seq.next?{/*what to do if exp*/}`. Правила значения обработчика, области перехвата и отличия от тернарной формы ещё нужно определить.

## Что ещё нужно решить перед реализацией соответствующих частей

1. Язык реализации компилятора, стандарт C, C toolchain и источник сигнатур импортированных функций. Пути заголовков, правила имени функции и линковка.
2. Разделители объявлений и выражений, ранний возврат и точка входа. Базовая сигнатура `sum(a:i,b:i):i{a+b}` уже выбрана.
3. Тип указателя и способы обращения к значению, допустимость `P=point(...)`, результаты `.cp`/`.dpcp`. `p=Point(...)` уже запрещено.
4. Конечная граница range, исчерпание `.next` без null, копирование и повторный обход sequence, вложенный контекст точки.
5. Семантика ленивой строки `(s)`: чтение частями, индексация, `.size` и моменты накопления данных.
6. Алгоритм освобождения недостижимых циклов, копии графов, возможный перенос стека в кучу, захваты и FFI-указатели. Набор поддерживаемых случаев может быть ограничен первым драфтом.
7. Типы литералов без суффикса, C-подобные преобразования в контексте фиксированной ширины типов lac, переполнение и короткое замыкание. Типа `y` нет.
8. Кодовая единица UTF-16 как точное значение `c` и единица размера, преобразование в C-строки, иммутабельность результата `.toS`, сигнатура `getIfPresentOr`.
