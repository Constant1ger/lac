# Последовательные программы без входной функции

По уточнению пользователя от 2026-10-02 код без определения входной функции может записываться прямо на уровне файла. Операторы выполняются последовательно в порядке записи. Компилятор создаёт внутреннюю входную функцию и применяет обычную проверку типов, владения и cleanup.

Эталон `code/zero5.l`:

```lac
a{n:i,tx:S}
f=a(2,"tt")
D=A(2,"tt")
prl(f#D)
prl(f~D)
```

Вывод — `false`, затем `true`, exit 0. `a{n:i,tx:S}` эквивалентно `a(n:i,tx:S)`; это описание типа, а не функция и не создание объекта. Обе формы работают и внутри явно заданной функции. Нижний/верхний регистр конструктора по-прежнему выбирает стек/кучу.

Последовательная программа допускает объявления переменных, выражения и вызовы, C import, числовые массивы и fe/fld, структуры и лямбды. Присвоенная лямбда сама не выполняется: `fun={prl("called")} fun()` вызывает её только второй инструкцией. Перед использованием переменная должна быть объявлена. Пробелы/новые строки разделяют операторы, точка с запятой допустима. Пустая программа успешно завершается.

## Выбор входа

Если заданы самостоятельные функции (`main`, `m`, именованные или отдельные `{...}`/`(){...}`), действуют прежние правила выбора входа. Смешение таких функций с исполняемыми операторами вне функций в текущем срезе диагностируется: операторы нужно поместить в main. Это ограничение реализации смешанного режима, а не требование выполнять глобальные операторы автоматически перед main.

Присвоенные функции/лямбды не являются самостоятельным входом. Они могут сопровождать последовательные операторы; если файл содержит только такие определения без вызовов/операторов и без самостоятельного входа, сохраняется диагностика отсутствия точки входа.

Импорты и описания типов обрабатываются компилятором до выполнения; последовательность относится к вычислению и побочным эффектам операторов.

`scripts/test-scripts.ps1` включён в общий тест: проверяет zero5, порядок выполнения, обе формы описания структур, C import, массив/fold, лямбду, пустую программу, cleanup и некорректные смешанные/типовые случаи.
