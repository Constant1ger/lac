# lac 0.0.1: согласованные границы и оставшиеся решения

Обновлено: 2026-10-02. Ответы пользователя на вопросы перед реализацией. Для версии 0.0.1 этот документ имеет приоритет над предыдущими планами и историческими примерами. Ревизия 2 действует там, где не изменена ниже. Компилятор ещё не реализован; рекомендации не являются принятыми требованиями.

## Принято

Последние уточнения 2026-10-02 имеют приоритет над более ранними пунктами ниже:

- Без определений самостоятельных функций код верхнего уровня исполняется последовательно. Описание структуры `a{n:i,tx:S}` эквивалентно `a(n:i,tx:S)`; zero5 использует эту форму вне функции. Реализованные правила выбора script entry и ограничения смешанного режима — [scripts.md](scripts.md).

- `{...}` и `(){...}` взаимозаменяемы для входа и функций/лямбд без аргументов; присваивание `fun={...}` допустимо и внутри функции, без захватов. Конструкторы a/A обозначают одну структуру с размещением соответственно на стеке/в куче. `#` сравнивает адреса, `~` значения полей; stack/heap формы одного типа сравнимы. Реализация и ограничения — [scopes-lambdas.md](scopes-lambdas.md), [structures.md](structures.md).

- По поручению реализовать test.l поддержано описание структуры `A(n:i,tx:S)` внутри функции, создание `B=A(2,"tt")` и обращение `B.tx.pr`. Явное описание и вызов конструктора различаются по `name:type` и значениям аргументов. Ограничения текущей реализации — [structures.md](structures.md).

- Тип каждого аргумента функции должен точно соответствовать типу параметра. Неявные числовые преобразования при вызове запрещены, даже если ранее разрешены C-подобные преобразования внутри арифметического выражения. Для параметра d нужны литерал `128d` или явное преобразование `d(value)`; `128` имеет тип i. Исправленный zero2.l использует `x=128d y=138d`.

- Числовой массив `i[n]` и аналоги floating point инициализируются нулями. Немедленный fe с записью может позволять пропустить начальное обнуление, если нет чтения старых значений до записи.
- fe изменяет каждый элемент существующего массива, новый массив не создаёт; цепочка работает с тем же контейнером.
- fld(a) инициализирует аккумулятор нулём, не первым элементом; явный initial задаётся `fld(a=...)`. Операция применяется ко всем элементам, её результат записывается в аккумулятор; пустой вход возвращает initial. Краткие `fld(a=0){.+a}` и `fld(a){+a}` эквивалентны. Это специальная operation-форма fld, не отмена @ у обычных лямбд.
- Значение без явной начальной инициализации в fld или функции получает ноль. Для нечисловых типов и пропущенных аргументов точное правило ещё следует описать; не вводить null как default.
- Лямбда, присвоенная переменной (`f=(...){...}`), не участвует в выборе entry. После main/m fallback — первая самостоятельная функция, в том числе анонимная `(){...}`.

- Пользователь подтвердил исправления zero.l: uppercase-владельцы, именованный аргумент используется по имени, копирующий конструктор требует явного `&`, например `Point(&P)`; создаётся независимый объект, источник сохраняется.
- Встроенная печать: `pr` = print без перевода строки, `prl` = println с переводом строки. Последнее уточнение заменяет имя `prln`; сохранение `prln` как алиаса не утверждено.
- `main` без возврата успешно завершает программу с кодом 0.
- `i(string)` пока разбирает число как `atoi`, без исключения при некорректном тексте. Возможная строгая версия с исключением отложена. Для bignum это правило разбора, а не обязательный вызов C `atoi` с результатом int.

- Компилятор lac реализуем на C; конкретный C-бэкенд ещё выбираем.
- `i/u` — расширяемые целые, `i32/u32/i64/u64` — фиксированные. Это заменяет прежнюю фиксированную ширину `i/u`.
- Для обсуждённого отрицательного результата беззнаковой операции (`u(0)-u(1)`) debug — паника, release — заворот. Если реализация паники задерживает 0.0.1, пользователь разрешил временный заворот в обоих режимах с переносом паники. У расширяемого `u` нет естественной фиксированной разрядности, поэтому модуль заворота ещё нужно определить. Не переносить решение автоматически на все прочие арифметические ошибки.
- Безымянный параметр `take(Point){}` доступен через `.`; при явно заданном имени используется объявленное имя. Имя переменной вызывающего не наследуется.
- Первую эталонную программу пользователь предоставил в `code/first.l`; исходник оставляем без изменений. Новые конструкции и расхождения разобраны в [first-program.md](first-program.md) и требуют уточнения.

- Ядро: числа, строки, функции, условия, структуры, массивы, лямбды.
- Коллекции List/Set/Map и sequence не входят сейчас; нужны в следующей версии. Неизменяемые аналоги коллекций сохраняются в плане.
- Текущая целевая платформа — Windows. Язык реализации — C; Clang допустим. Linux сохраняется общим направлением проекта, но проверка Linux не является подтверждённым критерием этой версии.
- Команды: `lac file.l @ app.exe`, `lac file.l`, `lac 'код' @ app.exe`, `lac 'код'`. Без заданного имени результат — `a.exe`; временная сборка и автоматический запуск остаются низким приоритетом. `@` в аргументах CLI обозначает имя результата, в исходнике — возврат; это разные контексты.
- Объявления через пробел сохраняются. Точка с запятой необязательна, но может разделять функции. Комментарии: `//` и `/* ... */`. Окончательное правило границ инструкций нужно формализовать в грамматике.
- Точка входа: `main` либо `m`; наличие обеих — ошибка компиляции. При отсутствии обеих выбирается первая функция.
- Входная функция получает неизменяемый массив параметров программы `S[]`, живущий всю программу. Имя исполняемого файла не входит. Точную сигнатуру ещё нужно нормализовать; не заменять обозначение `S[]` самостоятельно. «Статический» здесь означает время жизни, а не известную при компиляции длину.
- Возврат через `@val`. Если возвращаемый тип функции не указан, он выводится из возвращаемых выражений. Разные типы у нескольких `@` одной функции — ошибка компиляции, без неявного приведения к общему типу. Лямбда без `@` ничего не возвращает.
- Неизменяемость переменной задаётся `i` перед именем типа. Пользователь подтвердил `count:ii=3` для неизменяемого типа `i`. Граница неизменяемости вложенных объектов ещё требует утверждения. Не трактовать ответ как запрет всех изменяемых переменных.
- Лямбды пока не захватывают внешние локальные переменные. Доступ к глобальным функциям и именам типов не является захватом локальной переменной.
- `.cp` и `.dpcp` отложены.
- Строковая интерполяция `{expr}` включена. Буквальные фигурные скобки экранируются обратной косой чертой: `\{` и `\}`. Строки закрытые, неизменяемые ASCII, представление `{data, size}` без NUL.
- Логические `&` и `|` имеют короткое замыкание; `^` требует оба операнда, `!` — один.
- Индексация с нуля. Диапазон `a..b` не включает `b`. Выход за границы завершает программу с диагностикой. Поддержку самого Range в этой версии нужно отделить от отложенного Sequence.
- Сигнатуры C автоматически извлекаются из импортированного заголовка; первые вызовы ограничены числами и строками. Точные разрешённые C-типы, указатели, возвраты и строковые адаптеры нужно определить.
- Единственный владелец без GC и RC сохраняется. Выбран явный вариант A: `read(p&Point){}`, `edit(p*Point)`; вызовы `read(&P)`, `edit(*P)`. `*` в этом контексте означает исключительное изменяемое заимствование, а не принятую отдельно операцию разыменования.
- `take(Point){}` принимает владение без имени параметра; вызов `take(P)`. Внутри аргумент доступен через `.`. Если имя параметра задано, используется объявленное имя, не имя переменной вызывающего.
- Для целочисленного переполнения выбран bignum: `i/u` расширяемые, `i32/u32/i64/u64` фиксированные. Представление bignum и переход к C ABI ещё проектируются. Underflow беззнакового числа описан выше; деление на ноль, floating point и сужающие преобразования не определены.

## Вопросы после разъяснений

Добавлен другой пользовательский пример [zero.l](../code/zero.l), более близкий к согласованному ядру; [его разбор](zero-program.md) фиксирует оставшиеся детали. Исходные программы автоматически не исправляем.

1. C-бэкенд и объём статической проверки заимствований.
2. Модуль заворота расширяемого `u`, поведение фиксированных типов, деление на ноль, сужающие преобразования и floating point.
3. Расхождения первой эталонной программы с прежним минимумом; см. [разбор first.l](first-program.md).
4. Ожидаемый результат first.l и дополнительные эталонные программы.

Перед реализацией соответствующего участка нужно нормализовать: сигнатуру входа; границы инструкций; тип функции без `@`, проверку всех путей возврата; поддерживаемый поднабор C API. Эти детали не следует молча выводить из старых примеров.

## Предложения по реализации и владению

Выбран C, главный критерий — скорость компиляции. Rust, C++, C#, Go и Zig рассматривались как альтернативы. Прежняя рекомендация Rust не является текущим выбором.

Для импорта заголовков предлагается libclang: чтение сигнатур после обработки заголовков с правильными include paths, defines и целевой ABI. Наличие `.h` не заменяет линковку библиотеки. Макросы и произвольные C-указатели не становятся автоматически поддержанным lac API.

Вариант A выбран; синтаксис изменён пользователем:

```plaintext
read(p&Point){}
edit(p*Point){}
take(Point){}
read(&P)
edit(*P)
take(P)
```

После `read` и `edit` владелец остаётся у вызывающего. После `take` прежнее имя `P` недоступно. Тело `edit` в примере нормализовано добавлением `{}` к исходной записи пользователя. `&mut` из старого предложения заменён на `*` и не является принятым ключевым словом.

Вариант B с автоматическим заимствованием не выбран.

Для 0.0.1 предлагаются только заимствования на время вызова без сохранения в поле, возврата или захвата. Разрешены несколько читателей либо один исключительный изменяемый доступ. Это предложение об ограниченном безопасном поднаборе, а не обещание полного borrow checker Rust.

## Скорость компиляции: критерий и план сравнения

Нужно различать сборку самого компилятора и работу готового lac. Для пользователя существенна полная задержка `lac source @ exe`: запуск, чтение/разбор, проверка типов и владения, импорт C, генерация C, сборка C и линковка. Скорость исполнения полученного exe — третья отдельная метрика.

C выбран для компактного компилятора с быстрым запуском и непосредственным libclang C API. Но выбор C сам по себе не гарантирует победу над C++/Rust/Go/C#: алгоритмы, размещение AST, число аллокаций и C-бэкенд нужно измерить.

Для скорости генерации exe предлагается сравнить TCC с Clang без оптимизаций. TCC объединяет компиляцию, ассемблирование и линковку и имеет libtcc; пригодность конкретной сборки для Windows, архитектуры и C ABI требуется проверить. Старые цифры сайта TCC на Pentium 4 не являются замером lac или современных Windows.

Будущий воспроизводимый тест: короткая программа, программа около 1000 строк и более крупный набор; с импортом и без него; полная и повторная сборка. Фиксировать конфигурацию, отдельно измерять фронтенд, импорт, C-бэкенд и линковку, сравнивать медиану повторных запусков при одинаковом режиме оптимизации. До появления реализации и всех инструментов нет достоверных миллисекунд или ранжирования.

Для bignum предлагается компактное обычное представление малого целого с переходом к динамическому буферу при росте. Семантический тип не меняется. Это требует исполняемых арифметических функций и allocator, но не GC. Библиотеку или собственную реализацию не выбрали. Граница `i/u` расширяемые, `i32/u32/i64/u64` фиксированные для FFI утверждена пользователем.
