# Эталон zero2.l

Дата: 2026-10-02. Пользователь добавил [zero2.l](../code/zero2.l). Файл сохранён без изменений. Bootstrap-компилятор успешно собирает и запускает пример: случайная сумма, затем `10`.

## Сценарий

Импорт stdlib.h/time.h; именованное значение лямбды f с двумя d-параметрами вычисляет абсолютную разницу через тернарное ветвление. Анонимная входная функция инициализирует генератор случайных чисел, заполняет массив из 100000 целых через fe, сворачивает его в сумму, печатает сумму и результат f(128d,138d), ожидаемый по значению 10 типа d. Сумма случайна и не подходит для фиксированного ожидаемого вывода теста.

## Новые формы

- `import stdlib.h`, `import time.h` — конкретные заголовки без кавычек, автоматические C-сигнатуры остаются требованием.
- `f=(x:d,y:d){@x>y?x-y:y-x}` — объявление функции-значения на уровне файла, тип результата выводится по @. Нужно поддержать приоритет так, чтобы @ возвращал всё тернарное выражение.
- `(){...}` — самостоятельная анонимная функция, участвующая в выборе входа. Объявление `f=(...){...}` присваивает значение лямбды и не является кандидатом на вход; при отсутствии main/m выбирается первая самостоятельная функция. Поэтому в примере вход — `(){...}`, а не f.
- `time(null)` — пользователь явно допускает null как аргумент внешней библиотеки. Это не вводит null для переменных lac. C null здесь должен типизироваться как нулевой указатель, не как bignum-целое.
- `i[100000]` — создание массива с типом и размером. Числовые элементы, включая floating point, по умолчанию инициализируются нулём. При немедленном fe с записью значений начальную инициализацию можно оптимизировать; хранение буфера и допустимость размера ещё требуют реализации.
- `.fe{@rand}` — заполнение существующего массива без создания нового. Цепочка сохраняет тот же контейнер. rand вызывается без (); нужно отличать no-arg call от функции как значения.
- `.fld(a){+a}` — fold с выводимым типом аккумулятора; `.` означает текущий элемент. Аккумулятор без явно заданного начального значения инициализируется нулём, не первым элементом. Обрабатываются все элементы; после каждого шага аккумулятор заменяется результатом операции. Пустой массив возвращает начальное значение. `fld(a=0){.+a}` и `fld(a){+a}` эквивалентны для числовой суммы.
- `f(x,y).prl` — вызов обычной функции печати через точку. В исправленном файле `x=128d y=138d`; суффикс d задаёт double даже без десятичной точки. Прежние `x=128 y=138` имеют тип i и не подходят для параметров d: вызов обязан дать ошибку компиляции. Неявное числовое преобразование аргументов запрещено; явное `f(d(x),d(y))` допустимо при поддержке соответствующего конструктора преобразования.

## Подтверждённые правила

Пользователь расширил правило инициализации: если значение не получило явного начального значения в fld или другой функции, оно инициализируется нулём. Это изменяет прежний запрет объявления без явной инициализации: числовое значение всё равно создаётся инициализированным. Представление нуля для нечисловых типов и возможность пропуска аргумента функции не определены этим примером; не вводить внутренний null самостоятельно.

Краткий блок операции fld — специальная форма вычисления нового аккумулятора, как operation в Kotlin fold. `+a` разворачивается в сумму текущего элемента и a, результат записывается в a. Это не отменяет правило @ для обычных функций/лямбд; синтаксическое понижение fold нужно описать явно, не возвращая неявный результат всем лямбдам.

Пропуск первоначального обнуления — оптимизация, а не разрешение читать неопределённые данные. Его можно применять только при записи каждого элемента до первого чтения. Например, `fe{@rand}` не использует старое значение, а `fe{@(.+1)}` требует начальных нулей. Первая реализация может обнулять консервативно; это сохраняет семантику.

## Реализованный срез и ограничения

Буфер массива размещается в куче, размер и индекс пока int64; отрицательные размеры, переполнение размера и выход за границы диагностируются. Cleanup освобождает буфер без GC. `fe` сохраняет тот же буфер; присваивание другому имени передаёт владение. Немедленный полный fill без чтения текущего элемента пропускает обнуление.

Реализованы короткие блоки fe/fld с одним выражением и аккумулятором того же типа, что элемент. `rand` без скобок вызывается автоматически; хранение импортированной функции как значения ещё не поддержано. Присвоенные лямбды уровня файла поддерживаются, локальные — пока нет.

libclang извлекает реальные сигнатуры заголовков. Ограниченный C ABI поддерживает числа, входной const char* через NUL-адаптер и null для указательного параметра. Целые C-типы пока сведены к lac i/int64; аргументы приводятся к точному C-типу. Проверки диапазонов узких/беззнаковых C-типов, возвращаемые указатели, variadic и произвольные структуры требуют расширения.

Нулевые значения нечисловых типов и правила пропущенных аргументов требуют отдельной детализации. `i` пока int64, не bignum.

## Проверки

Отдельно проверять импорт и C ABI, time(NULL), rand() (C int → lac i), fill/fe, fold и тернарную лямбду. Для детерминированного теста использовать фиксированный seed либо отдельно проверять fold на небольшом известном массиве; файл пользователя не менять ради теста. Дополнительный bignum-тест должен превышать 64 бита: сумма 100000 результатов rand обычно не достигает такого диапазона.

Выполнены интеграционные проверки zero/zero2, числовых массивов, fe с возвратом и без него, чтения прежнего элемента, полного fold, пустого fold с нулём и initial 7, floating point, C import/string adapter, фиксированного seed и выбора entry. Тернарное условие вычисляет только выбранную ветку. Сборка и тесты проходят через GCC и Clang; CMake/MinGW собирает компилятор.

Проверено отдельно: функция `(x:d,y:d)` принимает `128d,138d` и отвергает `128,138` с диагностикой ожидаемого/фактического типа.
