# Актуальное состояние компилятора

Сводка на 2026-10-02, ветка `0.0.1`. Это рабочий прототип с генерацией C, а не завершённый релиз 0.0.1. Сводка описывает реализованные возможности; требования к будущим версиям и история решений сохраняются отдельно.

## Проверенные программы

| Исходник | Результат | Что проверяет |
| --- | --- | --- |
| `code/zero.l`, аргументы `4 5` | `falsetrue`, затем `x = 4, y = 5` | argv, структуры, копия, функции и строки |
| `code/zero2.l` | случайная сумма, затем `10` | C import, d, условие, массив, fe/fld |
| `code/zero3.l` | `9446744073709551607` | расширение i за пределы int64 |
| `code/test.l` | `tt` без перевода строки | объявление типа и строковое поле |
| `code/zero4.l` | `false`, затем `true` | bare-вход, стек/куча и сравнения |
| `code/zero5.l` | `false`, затем `true` | последовательная программа и описание типа через {} |

Все перечисленные программы успешно завершились с кодом 0 в последних проверках. Сумма zero2 не фиксируется в ожидаемом выводе, поскольку используется случайный seed.

## Реализованные правила

- Без самостоятельных функций операторы верхнего уровня выполняются по порядку. Описания типов и import обрабатываются компилятором. Смешение исполняемых глобальных операторов с самостоятельными функциями пока отклоняется; операторы нужно поместить в main.
- `main`/`m` имеют приоритет, их совместное определение запрещено; иначе выбирается первая самостоятельная функция. Присвоенная лямбда не становится входом. Пустой script допустим.
- `{...}` и `(){...}` эквивалентны для входа и лямбд без аргументов. `main{...}`, локальные и глобальные `fun={...}`, вызов `fun()` и алиасы поддержаны. Захватов внешних локальных переменных нет.
- Возврат только через `@`; без него функция/лямбда возвращает void. Тип результата выводится либо задаётся явно. В текущем срезе @ должен завершать тело функции.
- `i` — знаковое целое произвольной точности: int64 inline для малых значений, независимый буфер LibTomMath для больших. Поддержаны литералы, арифметика, сравнения, строковый разбор, печать и использование в структурах/массивах/функциях. `/` округляет к нулю, `%` имеет знак делимого; деление на ноль диагностируется.
- `d/f` и суффиксы `128d/3f` поддержаны. Аргументы функций lac требуют точного типа; i не преобразуется в d автоматически. Явное `d(value)`/`f(value)` доступно. Тернарное условие требует bool и вычисляет только выбранную ветку; `&`/`|` замыкаются коротко.
- Строки неизменяемы, записываются между двойными кавычками; литералы ASCII, представление `{data,size}` без NUL. Интерполяция `{expr}`, буквальные скобки `\{`/`\}`. `pr` печатает без перевода строки, `prl` — с ним. s/S пока трактуются одинаково как строковое значение; окончательное различие типов остаётся открытым.
- `a(n:i,tx:S)` и `a{n:i,tx:S}` описывают один тип. a/A различаются размещением конструктора: `a(...)` на стеке, `A(...)` в куче. Имена стековых значений lowercase, владельцев heap uppercase. Поля i/d/f/b/s/S строго проверяются.
- Стековое присваивание копирует поля независимо; heap-присваивание передаёт владение. Конструктор копирования требует `&`: `a(&D)` и `A(&f)` копируют между размещениями. Стековые параметры/результаты lowercase-типа передаются по значению. `#` сравнивает адреса, `~` — поля, включая содержимое строк; разные типы структур сравнивать нельзя.
- `i[n]`, `d[n]`, `f[n]` создают массивы; индексы с нуля, границы проверяются. fe с @ заменяет элементы того же массива, без @ выполняет действие. fld начинает с initial либо нуля, обрабатывает все элементы; пустой вход возвращает initial. Для i буфер обнуляется всегда, для f/d допускается пропуск обнуления при немедленном полном заполнении без чтения.
- Единственное владение, без GC/RC: компилятор вставляет освобождение объектов и буферов. Заголовок стековой структуры не освобождается через free. Заимствования временные для вызовов; сохранять или возвращать их как владельцев нельзя.
- C import извлекает сигнатуры через libclang. Поддержаны числа, входной const char* с NUL-адаптером и null для указательного C-параметра. Диапазоны C-аргументов, размеры/индексы и exit code проверяются; большие i не обрезаются молча. LibTomMath статически включается в exe.

## Воспроизведение

```powershell
./scripts/build.ps1
./scripts/test.ps1
./build/lac.exe code/zero5.l '@' build/zero5.exe
./build/zero5.exe
```

CLI принимает файл либо исходник строкой. Без `@ имя` создаётся `a.exe`; сгенерированный C сохраняется рядом как `имя.exe.c`. `LAC_CC` задаёт исполняемый файл C-компилятора. Компилятор собирается GCC или Clang; проверена также сборка CMake/MinGW. На текущем Windows-компьютере используются MSYS2 UCRT64, GCC 13.1, Clang/libclang 16.0.5, LibTomMath 1.2.0 и CMake 3.29.2. Linux остаётся целевой платформой, но текущие проверки выполнены на Windows.

Общий test.ps1 включает bignum, структуры, scopes и scripts. Арифметика сверяется с .NET BigInteger; проверяются диагностика типов/владения и баланс malloc/calloc/realloc/free, включая LibTomMath, на выбранных успешных программах. Это не универсальное доказательство безопасности памяти.

## Что ещё требуется

Не реализованы u и фиксированные целые типы, c/Unicode-строки, полноценные if/else и циклы/range, коллекции/Sequence, pipe/внешние утилиты, редактор с подсветкой, temp-run и кэш. Модель u underflow/wrap требует отдельного решения.

Локальные лямбды с типизированными параметрами, захваты, функциональные параметры/возвраты, heap-владение в параметрах, сохранённые заимствования, вложенные владельцы/коллекции/функции в полях и defaults требуют расширения. Таблица типов пока общая для файла; имена типов уникальны. fe/fld содержат одно выражение, аккумулятор соответствует типу элемента. Inline inferred Point/point пока выводит поля только как i. Большие числа пока не сжимаются автоматически обратно в малое представление.

C FFI не поддерживает variadic, возвращаемые указатели и произвольные C-структуры. Версия пока не заявляется завершённой.
