# Предварительная спецификация lac

Статус: проектирование, 2026-10-01. Ниже требования пользователя отделены от предложений и открытых вопросов. Примеры иллюстрируют обсуждавшиеся конструкции, а не готовую грамматику.

## Назначение

lac должен стать расширением или полной переработкой Bash: очень лаконичным языком работы с файлами и системными утилитами, поддерживающим возможности современного языка высокого уровня вроде Kotlin.

Требуется строгая типизация. Предусмотрены однократное выполнение и компиляция через `>>`; механизм исполнения и бэкенд пока не выбраны. Статическая проверка типов обсуждалась как предложение. Совместимость с существующими Bash-скриптами не определена.

## Требования пользователя

### Типы

| Обозначение | Назначение |
| --- | --- |
| `i32`, `i64` или сокращение `i` | Знаковые целые |
| `u32`, `u64` или сокращение `u` | Беззнаковые целые |
| `f`, `d` | Числа с плавающей точкой |
| `c` | Символ |
| `b` | Логический тип |
| `s` | Строка; в примере также обозначает тип без имени параметра |

Типы указателей обозначаются названиями типов с большой буквы. Пользователь также предложил стековое размещение объекта, созданного через такой указатель. Связь этого правила с подсчётом ссылок и временем жизни ещё не определена.

Размеры сокращённых типов, числовые преобразования, переполнение и семантика символа пока не утверждены.

### Имена и создание переменных

- Имена переменных не содержат цифр; используются camelCase или snake_case.
- Точный набор допустимых букв и символов предстоит определить.
- Ограничение цифр относится к именам переменных; обозначения типов `i32` и `u64` сохраняются.
- Создание переменной всегда включает инициализацию.
- `null` для присваивания переменным отсутствует.
- Синтаксис объявления переменных и обозначение изменяемости пока не выбраны.

### Блоки и ветвления

Области видимости задаются фигурными скобками `{}`.

Вместо `if` используется выражение:

```plaintext
значение_или_функция ? A : B
```

Ветвление может возвращать значение. Тип условия, правила вызова функции в условии, совместимость типов ветвей и вычисление только выбранной ветви требуют формального определения.

### Массивы, диапазоны и преобразования

Массивы используют квадратные скобки. Обсуждавшаяся запись создания и присваивания:

```plaintext
=[1,2,3]
```

Диапазоны: `1..9`, для символов — `a..z`. Требуется функциональность диапазонов, аналогичная Kotlin. Синтаксис символьных литералов, шаг, обратный обход и правила границ предстоит определить.

Обсуждавшиеся записи обхода:

```plaintext
(1..9){}
(a1..9){arr[a]+1}
arr(1..9).+1
```

Уточнение пользователя:

- `(a1..9){arr[a]+1}` вызывает лямбду в `{}` для индексов от 1 до 9 и возвращает соответствующие значения `arr` плюс 1.
- `arr(1..9).+1` возвращает значения элементов с индексами от 1 до 9, применяя к каждому `sum(value, 1)`.
- Эти примеры описывают возвращаемые результаты, а не присваивание новых значений элементам исходного массива.
- В сокращённой форме точка обозначает текущий элемент (`it`).

В документации следует различать диапазон индексов и последовательность вычисленных результатов. Пользователь уточнил: range должен работать как ленивая sequence, выдающая следующее значение через `.next`.

`[0...size]` в пользовательском примере означает диапазон от 0 до `.size`, где размер берётся у текущего массива `.`. Включение верхней границы и различие операторов `..` и `...` ещё не определены. Ленивость самого преобразования массива, начальный индекс массива, выход за границы и общие правила сокращённых операций также требуют уточнения.

`.collect` эквивалентно `.collect()`: функция собирает sequence в массив и закрывает sequence. Семантика закрытия, повторного использования и завершения при ошибке пока не определена.

Конструкция `array.{body}` обозначает обход каждого значения массива с выполнением блока. Это поэлементный обход, в том числе после `.collect`. Возвращаемое значение этой конструкции ещё не определено.

### Структуры и функции

- Поддерживаются структуры данных, в том числе анонимные и без имени переменной.
- Функции являются объектами/значениями, включая анонимные лямбды.
- Структуры могут содержать объекты функций.
- Методы описаны пользователем как синтаксический сахар; по умолчанию функции статические.
- Доступ к переменным/полям и методам объекта осуществляется через точку.
- Пользователь предложил: «объект — массив объектов, к нему можно обращаться как к массиву». Типизация и точная семантика такого доступа пока не определены.

Описание структуры использует фигурные скобки, вызов конструктора — круглые:

```plaintext
db_item{id:i,text:s,type="warn}
db_item([0...size].next,.)
```

`type="warn` задаёт значение поля по умолчанию с автоматически выведенным строковым типом. Конструктор может не передавать это поле.

По уточнению пользователя, запись `db_item([0...size].next,.,"warn)` также может совмещать вызов конструктора с определением структуры. Правила вывода имён полей и регистрации такой структуры пока не определены.

Методы без аргументов можно вызывать без круглых скобок: `.collect` и `.collect()` эквивалентны. Нужно определить различие между таким вызовом и получением функции как значения.

Точка входа — первая функция, в том числе анонимная. В примере это `(s){...}`, где задан тип строки без имени параметра. Входную функцию можно задать явно как `main()` или `m()`. Правила приоритета явной точки входа, выбора первой функции и передачи входных данных ещё требуют определения.

Нужно различить методы с получателем и поля, хранящие функции с захваченным окружением. Полная грамматика функций, захватов и анонимных структур ещё не выбрана.

### Строки

Строки обязательно открываются двойной кавычкой. Закрывающую кавычку можно опустить: по уточнению пользователя, строку закрывает любая закрывающая скобка `)`, `}` или `]`. Пользователь определяет строки как массивы `char`, с которыми можно работать как с массивами.

Предлагаемая детализация для парсера: завершающая скобка не входит в строку и остаётся токеном окружающей конструкции. Примеры применения правила:

```plaintext
print("hello)
db_item{type="warn}
["hello]
```

Ещё нужно определить экранирование закрывающих скобок, действие правила внутри строк с явной закрывающей кавычкой, конец строки на EOF и разделение нескольких строковых аргументов запятой. Запятая как завершитель строки не утверждена.

Незакрытые двойные кавычки в эталонном примере намеренны; нельзя автоматически считать их опечатками. Символьный литерал `'\n'` присутствует в примере, но его общая грамматика отдельно не определена.

Поддерживается интерполяция значений и доступ к внутренним значениям и методам:

```plaintext
"текст $val текст"
"text $val.lenght text"
```

`lenght` сохранено как в пользовательском примере; окончательное имя встроенного свойства не утверждено.

Обсуждались, но не утверждены: `${expression}` для произвольного выражения, запись вызова `$val.method()`, имя свойства `length`, экранирование `$`, правила преобразования значений в текст.

Не определены кодировка, смысл `char`, изменяемость строк и стоимость индексного доступа. Требуется поддержка регулярных выражений.

### Pipe, файлы и программы

Оператор `|` поддерживает функциональный стиль, аналогичный по назначению Bash-конвейерам, с возможностями преобразования данных уровня Kotlin.

Требуется работа с системными утилитами, включая `grep`, `cat`, `tail`.

Открыты: синтаксис запуска, поиск исполняемых файлов, аргументы, окружение, рабочая директория, перенаправления, потоки `stdin/stdout/stderr`, статусы, отмена и обработка ошибок.

Предложения для обсуждения:

- Отличать типизированные последовательности от потоков байтов внешних процессов.
- Передавать аргументы отдельными значениями, без неявного исполнения строки через Bash.
- Обеспечить потоковую обработку без обязательной загрузки всего вывода в память.
- Явно описать преобразование байтов в строки и типизированные значения.

### Режимы запуска и сборки

- Без `>>` программа выполняется один раз.
- `>> script.exe` компилирует весь сценарий исполнения в исполняемый файл, включая этап с `grep`.
- Если после `>>` имя не задано, результат сохраняется как `a.exe` или `a.out`; правило выбора имени и платформы нужно определить.
- `>>` здесь означает сборку, а не дописывание стандартного вывода в файл.

Требование «вместе с grep» пока не определяет механизм: включение исполняемой утилиты в результат, встроенную реализацию её поведения или иной способ упаковки. Нужно уточнить, должен ли результат работать без установленного `grep`, а также обработку командной строки вызывающей оболочкой и передачу исходника lac.

### Редактор и подсветка

Запуск `lac` без аргументов открывает редактор кода. Требуется подсветка определений переменных, функций, структур данных и других конструкций языка.

Тип интерфейса редактора пока не выбран. Подсветка должна учитывать контекстные границы строк, описания структур и функции без имён параметров. Обсуждаемое предложение: использовать общий разбор исходника для редактора и исполнения, а разрешение имён — для семантической подсветки.

### Эталонный сценарий

Исходная пользовательская запись, без исправления необязательных закрывающих кавычек:

```plaintext
lac grep -Ei "warn|warning" app.log | db_item{id:i,text:s,type="warn} (s){.split('\n')[..].db_item([0...size].next,.).collect.{STD.Db("localhost:5432,"login:psw).save(.);STD.HttpCli("localhost:8089).post(STD.toJson(.))} >> script.exe
```

Сценарий задаёт поиск строк, описание структуры с полем по умолчанию, строковую входную функцию, разбиение вывода, преобразование строк в записи, сбор в массив и поэлементные действия сохранения и HTTP-отправки; `>>` задаёт сборку всего сценария.

Открытые вопросы примера: значение `[..]`, получатель `.size` внутри преобразования, единственное создание и состояние range для последовательных `.next`, завершение range, граница первого строкового аргумента в `STD.Db("localhost:5432,"login:psw)`, драйвер БД, обработка ошибок и время жизни клиентов БД/HTTP. Формальная семантика точки в каждом вложенном контексте ещё не определена.

### Начальная модель памяти

Последнее решение пользователя: пока использовать простые умные указатели с подсчётом владений; когда все ссылки вышли из scope, помечать объект на удаление.

Предыдущий ориентир — быстрая и безопасная модель, похожая на Rust. Полноценная проверка заимствований не является требованием начальной реализации.

Детали, предложенные ассистентом, но ещё не утверждённые:

- Учитывать владеющие ссылки в переменных, структурах, массивах и замыканиях.
- Увеличивать счётчик при копировании указателя, уменьшать при его уничтожении или перезаписи; перемещение не увеличивает счётчик.
- Освобождать объект немедленно при нулевом счётчике вместо отложенного удаления.
- Предусмотреть слабые ссылки для разрыва циклов и специальный тип отсутствующего результата.
- Начать с однопоточного исполнения.

Необходимые решения: момент фактического удаления, циклы владения, совместное изменение, потокобезопасность, стековые объекты и захваты лямбд. Подсчёт ссылок сам по себе не решает эти вопросы.
