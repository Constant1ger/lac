# Эталон zero.l

Дата: 2026-10-02. Пользователь добавил [zero.l](../code/zero.l) как другую программу lac. Исходник прочитан и сохранён без изменений. Он не отменяет автоматически предыдущие решения и не означает, что программа уже компилируется.

## Сценарий

Программа получает два аргумента, преобразует строки в целые `i`, создаёт Point с полями x/y, создаёт копию, сравнивает адреса (`#`, ожидается false) и значения (`~`, ожидается true). Затем сохраняет fakeMain как значение функции, вызывает через неизменяемое заимствование и печатает интерполированную строку.

Пример существенно ближе к текущему ядру 0.0.1: не требует коллекций, фильтра/map, sequence или захвата лямбд; строковые литералы ASCII. Явный main имеет приоритет над расположенным первым fakeMain.

## Нужные операции

- Индексный доступ к массиву аргументов с диагностикой границ.
- Преобразование строки в bignum `i` с временным atoi-подобным разбором, без исключения при некорректном тексте.
- Определение структуры через именованные поля конструктора; создание объекта в куче.
- Копирующий конструктор `Point(&P)` с явным заимствованием. Он создаёт независимый объект и сохраняет источник. Методы `.cp`/`.dpcp` по-прежнему отложены.
- Сравнение адресов и значений одинаково типизированных объектов.
- Значение функции без захватов, вызов по переменной и read-only заимствование.
- Интерполяция полей и печать bool/строки.

## Подтверждённые уточнения

- Heap-владельцы называются `P`/`Pnt`; пользователь подтвердил прежнее правило регистра.
- Именованный параметр `p&Point` используется как `p.x`/`p.y`; точка не становится его неявным алиасом.
- Конструктор копии требует `&`.
- `pr` — print без перевода строки, `prln` — println с переводом строки. `prl` не утверждён.
- `main` без возврата даёт exit code 0.
- `i(string)` пока работает как atoi: пропускает начальные пробельные символы, читает необязательный знак и начальную последовательность десятичных цифр, останавливается на следующем символе; если цифры не прочитаны, результат 0. Возможный вариант с исключением отложен. Для bignum предлагается тот же разбор непосредственно в расширяемое число, без промежуточного ограничения C int. [Документация atoi](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/atoi-atoi-l-wtoi-wtoi-l).

## Состояние файла после сообщения об исправлении

При повторном чтении uppercase-имена уже изменены, но в сохранённом файле ещё видны `{@"x = {.x}, y = {.y}"}`, `Pnt = Point(p)` и вызовы `prl`. Согласно подтверждённым правилам нужны поля `p.x`/`p.y`, `Pnt = Point(&P)` и `prln`. Файл автоматически не исправляли: пользователь редактирует эталон.

## Оставшиеся вопросы

Объявленный результат `:S` и локальное `str` требуют уточнения отношения `s/S`, heap-владения строки и правила регистра встроенных типов. Комментарии задают ожидаемые значения false/true, но точное оформление печати bool ещё не определено.

## История первоначальных расхождений

Пункты ниже сохранены как история; решения выше имеют приоритет.

1. `p=Point(...)` и `pnt=Point(p)` противоречат принятому правилу uppercase-имени heap-владельца. Ранее такая запись была ошибкой компиляции; нужно либо подтвердить `P`/`Pnt`, либо изменить правило регистра. Файл автоматически не исправлять.
2. В `fakeMain(p&Point)` параметр назван p, но тело использует `.x`/`.y`. Ранее точка согласована для безымянного параметра. Нужно определить, разрешена ли она как алиас единственного именованного аргумента.
3. `Point(p)` по ожидаемым комментариям должен создать независимый объект и сохранить p, а не переместить владение. Нужно утвердить автоматическое чтение исходника конструктором либо явное `Point(&P)`. Это не два владельца одного объекта.
4. `pr` и `prl` не сопровождаются import. Нужно определить, являются ли они встроенными функциями 0.0.1; различие перевода строки и формат bool, включая регистр, пока не утверждены. Ранее также встречались `prln`/`println`.
5. Объявленный результат `:S` и локальное `str` требуют уточнения отношения `s/S`, heap-владения строки и правила регистра для встроенных типов.
6. `main` не возвращает значение: нужно определить успешный exit code (предлагается 0).

Предполагаемый результат исправленного примера для аргументов `4 5`: значения false, true и строка `x = 4, y = 5`. Первый `pr` не добавляет перевод строки, последующие `prln` добавляют. Недостаток аргументов завершается диагностикой границ; некорректный текст числа обрабатывается atoi-подобно.

## Предложенный минимальный рубеж

После нормализации эталона использовать zero.l для сквозного прототипа: CLI → lexer/parser → типы и владение → C → exe. Первую реализацию проверять на корректном запуске, недостатке аргументов, atoi-подобном разборе некорректного текста и обращении к владельцу после передачи. Это план, не уже выполненные тесты.
