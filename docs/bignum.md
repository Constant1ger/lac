# Целые числа i

Реализовано 2026-10-02. `i` — знаковое целое произвольной точности. Диапазон ограничен доступной памятью, а не 64 битами. Малые значения хранятся непосредственно в `int64_t`; при выходе за его диапазон результат получает буфер LibTomMath. GC и подсчёта ссылок нет.

Поддержаны большие десятичные литералы, `+ - * / %`, отрицание, сравнения, печать, интерполяция, atoi-подобный `i(string)`, аргументы и результаты функций, поля структур и массивы `i[n]`. Присваивание примитива сохраняет семантику копирования значения; большой буфер копируется независимо. Временные буферы, поля и элементы освобождаются кодом, вставленным компилятором. Малое число не требует выделения памяти. Большой результат пока не сжимается автоматически обратно в малое представление.

Деление округляется к нулю; знак ненулевого остатка совпадает со знаком делимого, как у C. Деление и остаток от деления на ноль завершают программу с диагностикой. Преобразование `d(i)`/`f(i)` может терять точность согласно целевому floating point типу.

## Границы с внешним миром

Размеры и индексы массивов преобразуются в int64 с проверкой диапазона, затем проверяются размер выделения и границы массива. Код завершения программы проверяется на допустимость C int. Передача `i` в числовой параметр C проверяет знак и диапазон соответствующего типа из заголовка. Слишком большое значение не обрезается молча. Возвращаемые C signed/unsigned значения преобразуются в `i` без потери диапазона до 64 бит включительно.

Сборка сгенерированного C статически связывает `libtommath.a`. Программе не нужна отдельная DLL LibTomMath; для компиляции нужны её заголовок и статическая библиотека. Пути передаются в lac при его сборке через `scripts/build.ps1` или CMake. Импорт C по-прежнему требует libclang у самого компилятора.

Целочисленные массивы обнуляются до fe: это обеспечивает корректную начальную инициализацию владельцев больших буферов. Пропуск обнуления для немедленного полного заполнения остаётся оптимизацией будущего; для f/d прежняя оптимизация сохранена.

## Проверка

`scripts/test.ps1` включает `scripts/test-bignum.ps1`. Тест сравнивает 105 результатов арифметики/сравнения с независимым .NET BigInteger для малых, граничных и больших положительных/отрицательных чисел. Дополнительно проверяет копии, параметры/возвраты, повторное заполнение массива и fold, структуры, строковый разбор и интерполяцию, условные ветки, а также ошибки границ C ABI, размеров/индексов и exit code.

`tests/allocation_check.c` через linker wrapping считает malloc/calloc/realloc/free, включая статически связанную LibTomMath. После успешного выполнения программ с большими числами количество живых выделений должно вернуться к значению перед запуском пользовательского кода. Это проверка освобождения в данных сценариях, а не универсальное доказательство безопасности памяти.

`code/zero3.l` вычисляет `9223372036854775800 + 223372036854775807` и печатает `9446744073709551607`, exit 0.

`u` и фиксированные целочисленные типы остаются следующими этапами; данный срез реализует bignum для `i`.
