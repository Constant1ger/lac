# Реализация lac 0.0.1

Начало: 2026-10-02. Ветка `0.0.1`. Пользователь разрешил устанавливать нужные инструменты и коммитить законченные этапы. Требования — `version-0.0.1.md`; первый сквозной эталон — `code/zero.l`.

## Инструменты

- C-компилятор GCC уже найден в MSYS2 UCRT64; используем для bootstrap и сборки генерируемого C.
- CMake и Git установлены. PowerShell используется для сборки и интеграционных проверок; Python/Node не обязательны.
- Clang/libclang установлен: MSYS2 UCRT64 Clang 16.0.5, `libclang.dll`; используется для C import.
- LibTomMath установлен: MSYS2 UCRT64 1.2.0; используется для расширяемого `i`, статически линкуется в exe. `u` остаётся следующим этапом.
- TCC не нужен для первого корректного прототипа; его сравнение с GCC/Clang — последующий этап измерения скорости.

Воспроизводимая установка дополнительных пакетов: `scripts/setup-tools.ps1`. Используется штатный pacman существующего MSYS2; общий update системы не выполнялся. [MSYS2: установка пакетов](https://www.msys2.org/docs/package-management/).

## Выполненный первый этап

Исправлен эталон, добавлены lexer/parser, таблицы имён и проверка ограниченного поднабора типов/владения, C-генератор, CLI и автоматическая сборка GCC. `zero.l` исполняется с ожидаемым выводом. Есть `scripts/build.ps1`, `scripts/test.ps1` и CMake.

Структуры с явным описанием имеют i/d/f/b/s/S-поля и учитывают cleanup строк/bignum; inline inferred Point сохраняет i-поля, перемещение проверяется для именованных владельцев, заимствования не хранятся и не возвращаются. Строковые данные `{data,size}` не требуют завершающего NUL; для числового разбора временно создаётся C-адаптер. Cleanup генерируется для каждого владеющего временного значения.

Это первый сквозной срез. Bignum для i реализован: малое значение int64 хранится inline, большие значения используют независимые буферы LibTomMath с автоматическим cleanup. C-границы проверяются на диапазон. Следующий срез реализовал zero2: числовые массивы, fe/fld, f/d, тернарное условие, inferred returns, присвоенные лямбды уровня файла и ограниченный C FFI через libclang. Полные числовые типы, локальные лямбды, if/else и обобщённый FFI остаются дальнейшими этапами.

Проверено: сборка самого lac с `-Wall -Wextra -Wpedantic -Werror` GCC и Clang; CMake/MinGW Makefiles; интеграционные проверки с GCC и Clang как бэкендами. scripts/test.ps1 включает zero, atoi-подобный разбор, bounds, inline source, путь с пробелами, short-circuit logic, escaped braces/interpolation и 21 негативный случай; добавлены zero2, пустой fold, numeric arrays, fe/fld, f/d, C import, короткое замыкание тернарного условия и строгие аргументы вызова. scripts/test-bignum.ps1 включён в общий тест: арифметика сравнена с .NET BigInteger, проверены копии/возвраты/массивы/структуры/строки, границы C и баланс выделений памяти.

## Порядок выполнения

1. Исправить `Point(&p)` на `Point(&P)`, создать структуру проекта, сборку, lexer и диагностику с позицией в исходнике.
2. Parser выражений и блоков: объявления через пробел, функции, аргументы read/edit/owned, возврат `@`, вызовы, поля, индексы, строки/интерполяция, условия, массивы и лямбды без захватов.
3. Семантика: таблицы имён/типов, описание структуры по именованному конструктору, проверка заимствований и перемещения, единый тип всех `@`, неизменяемость. Неподдержанные операции отклонять явно.
4. Сквозной zero.l: сгенерировать C, автоматически освободить владельцев и строки, собрать exe; аргументы argv без имени программы; `pr/prl`; Point copy через &; `#/~`; функция-значение.
5. Расширить ядро числами bignum, фиксированными числами/f/d, операциями, массивами и условиями; добавить позитивные и негативные программы. Bignum i завершён; фиксированные типы и u требуют продолжения.
6. C FFI: libclang извлекает сигнатуры, поддерживается утверждённый поднабор чисел/строк; NUL-адаптеры, безопасная передача аргументов и код ошибки C-компилятора.
7. Проверить весь заявленный минимум, диагностику, cleanup при раннем возврате и ограничения; измерить фронтенд и полную сборку отдельно. Документировать реально реализованные возможности.

## Проверки

- `zero.exe 4 5`: `falsetrue` и `x = 4, y = 5`, exit 0.
- Недостаток аргументов: диагностика границ и ненулевой exit.
- `i("abc")` → 0; atoi-подобное чтение начального числа.
- Неизвестное имя, wrong constructor borrow, несовместимые типы, use-after-move, immutable reassignment, захват локального имени: ошибка компиляции.
- Реализовано для d: функция с d-параметрами принимает `128d/138d`, отвергает i-аргументы `128/138`; суффикс d работает без десятичной точки. Автоматическое widening при вызове не допускается.
- Число больше 64 бит сохраняется точно; для unresolved unsigned bignum wrap не вводить случайный модуль без решения.
- Файл, inline-исходник, имя exe с пробелами и `@` в CLI; отсутствие компилятора и неуспех внешней сборки.

## Неопределённые детали

Второй эталон — `code/zero2.l`; [разбор](zero2-program.md) связывает его с этапами массивов, лямбд/условий, bignum и C FFI. Инициализация числового массива нулевая; fe работает на том же буфере, fld начинает с initial/нуля и обходит все элементы, assigned lambda исключается из entry. Разрешение null в C-аргументе явно подтверждено комментарием пользователя; nullable-переменные lac не добавляются. Bootstrap компилирует и запускает этот пример без изменения исходника.

Для реализации эталона `S` в возвращаемом типе временно трактуется как неизменяемая строка-значение с владением буфером, без требования uppercase-имени локального handle; это явное техническое допущение до решения `s/S`. Встроенные `pr/prl` печатают bool как `false/true`. `.i` — сахар `i(value)`. Конструктор копирования Point копирует поля значений; правило графов с вложенными владельцами должно быть отдельным.

Debug/release underflow расширяемого u требует определения модуля; сборка не должна обещать его поддержку раньше решения. Полная готовность 0.0.1 отличается от первого рабочего сквозного среза.
