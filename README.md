# lac

lac — проект лаконичного языка для работы с файлами, системными утилитами и потоками данных. Идея — расширение или полная переработка Bash с возможностями современного языка высокого уровня, ориентиром служит Kotlin.

Начата реализация компилятора на C. Рабочий bootstrap-прототип компилирует `code/zero.l`, `code/zero2.l` и `code/zero3.l` через C в exe; полная версия 0.0.1 ещё разрабатывается.

## Сборка и запуск прототипа

Нужны GCC, Clang, libclang и LibTomMath в MSYS2 UCRT64; DLL libclang должна быть доступна в PATH. LibTomMath статически связывается с исполняемыми программами. На текущем компьютере инструменты установлены. `scripts/setup-tools.ps1` устанавливает дополнительные пакеты. Альтернативная сборка предусмотрена через CMake 3.19+.

```powershell
./scripts/build.ps1
./scripts/test.ps1
./build/lac.exe code/zero.l '@' build/zero.exe
./build/zero.exe 4 5
./build/lac.exe code/zero2.l '@' build/zero2.exe
./build/zero2.exe
./build/lac.exe code/zero3.l '@' build/zero3.exe
./build/zero3.exe
```

Вывод: `falsetrue`, затем `x = 4, y = 5`; код завершения 0. В PowerShell `@` CLI передаётся отдельным строковым аргументом. Без заданного имени создаётся `a.exe`; рядом сохраняется сгенерированный C (`a.exe.c`). Можно передавать исходник строкой вместо пути. `LAC_CC` задаёт путь к C-компилятору без дополнительных shell-аргументов.

Прототип поддерживает функции с явным или выводимым по `@` результатом, присвоенные лямбды уровня файла, анонимный вход, argv, печать, строки и интерполяцию, структуры с целочисленными полями, копирование через `&`, сравнение адресов/значений, `f/d`, тернарное условие, числовые массивы и встроенные `fe/fld`. `fe` изменяет тот же массив; `fld` обходит все элементы, включая первый, а для пустого массива возвращает initial или ноль. `zero2` печатает случайную сумму, затем `10`.

Поддержано явное объявление `A(n:i,tx:S)` внутри функции и конструктор `B=A(2,"tt")`. Объявленные структуры допускают поля i/d/f/b/s/S; копирование и cleanup учитывают строковые и bignum-буферы. `code/test.l` печатает `tt`. [Правила и ограничения структур](docs/structures.md).

`{...}` и `(){...}` эквивалентны для входа и лямбд без аргументов. Локальные `fun={...}` вызываются как `fun()` и не захватывают внешние локальные переменные. Конструктор `a(...)` создаёт стековое значение, `A(...)` — владельца в куче; тип один. Стековые значения копируются и передаются/возвращаются по значению. `zero4.l` печатает `false`, затем `true` при сравнении адресов и полей stack/heap объектов. [Блоки и лямбды](docs/scopes-lambdas.md).

Без самостоятельных функций операторы верхнего уровня выполняются последовательно. `a{n:i,tx:S}` описывает структуру как `a(n:i,tx:S)`. `code/zero5.l` компилируется в этом режиме и печатает `false`, затем `true`. [Последовательные программы](docs/scripts.md).

`import` извлекает сигнатуры из заголовков через libclang. Поддержан ограниченный C ABI: числовые значения, входной `const char*` с временным NUL-адаптером и `null` для указательного параметра. Variadic-функции, возвращаемые указатели и произвольные C-структуры отклоняются. Аргументы функций lac требуют точного типа: `128` не подходит для параметра `d`, нужно `128d` или `d(128)`.

Владельцы, массивы и временные строки освобождаются сгенерированным cleanup без GC. Буфер числового массива размещается в куче. Массивы `i` инициализируются нулями; для f/d при немедленном полном заполнении `fe` без чтения прежнего элемента обнуление пропускается.

`i` поддерживает произвольную точность: малые числа хранятся в int64, большие используют LibTomMath. `zero3` печатает `9446744073709551607`. Арифметика, печать, строки, функции, структуры и массивы сохраняют большие значения; C-аргументы, размеры/индексы и exit code проверяются на допустимый диапазон. Подробнее — [bignum](docs/bignum.md).

Ограничения текущего среза: `u`, фиксированные целые типы, обычные `if/else`, локальные лямбды с типизированными параметрами, коллекции и sequence ещё не реализованы. Блоки `fe/fld` пока содержат одну операцию. Параметры владения/мутации и вложенные владельцы структур также требуют расширения. Это не готовый релиз 0.0.1.

## Основные направления

- Строгая типизация; точные правила проверки и преобразований предстоит определить.
- Краткий синтаксис, пригодный для однострочных программ.
- Функции как значения, лямбды, структуры и преобразования коллекций.
- Конвейеры через `|` и запуск системных утилит, включая `grep`, `cat`, `tail`.
- Инициализация при создании переменных, без присваиваемого `null`.
- Единственный владелец, как в Rust: передача владения и автоматическое освобождение без GC, с минимальным runtime.
- Неизменяемые ASCII-строки `{data, size}` без завершающего NUL; неизменяемые аналоги коллекций, включая `iList`, `iSet`, `iArr`.

Первый драфт для Linux и Windows генерирует C и допускает вызовы функций C через явный импорт заголовков. Сейчас сборка создаёт файл с заданным названием либо `a.exe`; имя задаётся через `@`. Компиляция во временную папку, однократный запуск и кэш — низкий приоритет. Внешние системные команды остаются последующей стадией; долгосрочно запуск `lac` без аргументов открывает редактор с подсветкой.
